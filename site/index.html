02 · AI-assisted quality engineering

I use LLMs where they are strong, drafting, reading and summarising, and keep them away from the one decision they are poor at: what a test should mean. Every proposal passes a deterministic check and a human reviewer before it reaches CI.

2.1 Test generation

Claude Code, Codex and Playwright Agents draft risk-based plans and specs. A guardrail lint rejects sleeps, brittle selectors and missing assertions before a reviewer ever sees them.

2.2 Failure triage

Agents read CI logs, traces and diffs, group failures by likely cause and draft a first diagnosis: product bug, test bug or environment. The engineer confirms; the agent never marks a test green.

2.3 LLM evaluation

Features built on models get tests too. Promptfoo suites score outputs against rubrics and regressions in CI, so a prompt or model change is reviewed like a code change.

2.4 Infrastructure for agents

MCP servers give agents the same safe interfaces people use. TestLease exposes exclusive test account leases over MCP, so an agent running tests cannot collide with a CI worker.

In practice: TestPlan Studio ↗ turns an application description into a risk-based plan with Claude, compiles the browser scenarios into a linted Playwright spec, and runs it on GitHub Actions.

  2. TestLease

    v0.2 on npm

    Exclusive, expiring leases on shared test resources, for CI workers and AI agents.

    Parallel workers fight over shared accounts and sandboxes, and the flakiness looks like application bugs. TestLease gives each worker an exclusive lease: one owner per resource enforced by the database, a heartbeat for slow workers and a TTL that frees crashed ones, fair waiting, quarantine for contaminated accounts and an event trail as evidence. Secrets never leave the server. Ships as an HTTP API, Playwright fixtures, a CLI and an MCP server.

    7 npm packages at v0.2.0 · 129 automated tests · 8 Chromium workers on 3 accounts, 0 overlaps · 15 ADRs · Docker image on GHCR · Apache-2.0

  3. Trident

    v1.0.0 on Maven Central

    A modular Java 21 web and API automation framework, consumed as a dependency instead of forked.

    Java teams start each test project by copying the plumbing from the last one, and the copies drift. Trident is built around a single Cucumber runner with the REST Assured API layer shipped and web and mobile to follow. Generate a project from the archetype, depend on the modules you need, write feature files. It is developed against a 2005 JSP banking app with no test hooks, and a separate showcase adopts it from Maven Central against an unrelated application.
